PATTERN + CONTEXT
Step-by-step instructor guide and student questions
  1. Start with organic-like browsing and note the paths, pauses, and response mix.
  2. Run a 60 BPM heartbeat, then compare 72, 90, and 100 BPM. Each visual pulse creates one in-memory visit event.
  3. Choose irregular rhythm and discuss why timing anomalies need context rather than an automatic verdict.
  4. Run automated page pattern with defenses off, then on. Compare repeated-pattern, rate-limit, and blocked-event signals.
  5. Run synthetic login failures. The lab uses no credential input; discuss why repeated failures can indicate risk and how progressive delays or account lockouts help.
  6. Stop, reset, and explain what a real response team would correlate: source reputation, route, session, user impact, and application logs.

Discussion: What changed when defenses were enabled? What evidence would you need before deciding that activity was malicious? Why should generated lab events stay separate from business analytics?

Scope: HTTP codes and defenses are illustrative client-side models only; this lab does not include a WAF, server, authentication endpoint, or load test.
