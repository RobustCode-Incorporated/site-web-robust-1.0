# Article Brief Template

Copy this into a new brief before writing any article. Fill every field — an empty field usually means the topic isn't ready yet.

```
Title (working):
Target audience:
Search intent (what is someone typing into Google right before they'd want this article?):
Primary keyword:
Secondary keywords:
Question being answered:
Unique insight (what will this say that the top 3 ranking pages don't?):
Relevant Belgian context:
Relevant Robust Code product (if any, honestly — not every article needs one):
Relevant tool (if any):
Internal links planned (2-3 existing articles/tools/pages):
External authoritative sources to verify claims against:
CTA (product / tool / newsletter / consultation — pick the one that actually fits):
Category: (belgium | business | ai | automation | operations | case-studies)
Draft due date:
Fact-check required? (yes if it touches law, regulation, prices, or current events — see spec §23)
```

## Fact-check rule

If "Fact-check required" is yes, do not set `draft: false` in the frontmatter until a named person has confirmed the specific claims against a current, authoritative source (official government page, the actual regulation text, a primary source) — not a summary blog post, not memory, not this template. Record what was checked in the PR description, not in the article itself.
