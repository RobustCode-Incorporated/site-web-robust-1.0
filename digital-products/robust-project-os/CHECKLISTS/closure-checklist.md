# Closure Checklist (Stage 13)

This is the deeper, paid-tier closure checklist — it goes further than the free `project-success-checklist` tool on the website, which covers a retrospective and formal sign-off only. This version adds handover and knowledge-capture, which most informal projects skip entirely.

## Deliverable validation
- [ ] Every deliverable has been checked against its Stage 04 "definition of done."
- [ ] Any deviation from the original scope is documented, with the reason.

## Handover
- [ ] Whoever will maintain/use the deliverable going forward has been identified by name.
- [ ] They've received whatever they need to do that (access credentials, documentation, a walkthrough) — not just the deliverable itself.
- [ ] Any recurring cost or maintenance requirement created by this project (hosting, licenses, subscriptions) is documented and assigned to an owner.

## Knowledge capture
- [ ] A short retrospective is written down: what to repeat next time, what to change. Not just discussed — written down, or it won't survive to the next project.
- [ ] Any reusable template or process created during this project is saved somewhere the team will actually find it again.

## Formal closure
- [ ] Stakeholders are formally told, in writing, that the project is closed.
- [ ] Any outstanding items that did NOT get done are explicitly listed as "not done" — not left ambiguous.
